### 一句话

手机是**控制塔**：先看电脑、Agent、任务、交付物；聊天只是任务里的一种输入。

### 两步走

| 阶段 | 底部 tab | 聊天放哪 |
|---|---|---|
| **1+2 壳** | 总览 / 智能体 / 交付物 / 控制 | 总览底部命令条；点运行卡片进“任务详情”（路由/全屏层），不是 tab |
| **1+2+3** | 总览 / 智能体 / 任务 / 交付物 | 任务详情里的“对话 / 计划 / 日志 / 产出”；控制收进总览 + 我的抽屉 |

### 页面

**总览**（默认页）
- 顶部：当前电脑、在线、设备数、待批数
- **待你决定**：真实审批 + 待验收交付物，一条收件箱
- **智能体矩阵**：真实 Executor + Planner/Reviewer/“拉取 Agent”占位（P2，灰显）
- **运行中**：真实当前会话、进度、用的 Agent
- **电脑**：入口、设备、延迟；CPU/内存等指标没有数据就不画假数
- **最近交付物**：真实本轮/最近产出
- 底部命令条：`对 Agent 说…`，发给当前 Agent/任务

**智能体**
- 已安装 / 矩阵 / 可拉取
- v1 只显示真实 Executor；Planner/Reviewer/Coder/Researcher/Operator 是 P2 占位，不假装可拉取/可切换
- 点真实 Agent → 它的任务列表
- **外部 AI（D 阶段，未开工）**：DeepSeek / 豆包这类桌面 AI 客户端，
  标“外部 AI”，不按 ACP Agent 假装；Host 侧连接器，API 优先、GUI 兜底。
  见 `docs/task-desktop-ai-bridge.md`。

**任务**（1+2+3）
- 待批 / 运行中 / 待验收 / 已结束
- 每行：标题、Agent、最后活动、待批数、产出数
- 点进任务详情

**任务详情**（聊天唯一的主场）
- 顶部：任务标题、Agent、状态、进度
- 分段：对话 / 计划 / 日志 / 产出
- 对话里有审批卡、产出卡；底部继续输入
- 返回任务列表/总览

**交付物**
- 先复用“本轮/最近产出”；全仓库筛选（按会话/状态/时间）需要 host 新 API，放下一卡
- 每项：类型、会话、时间、大小、sha256、待验收/已收/已打回
- 点开预览；确认/打回仍绑原件 sha256

**控制**
- 1+2 阶段是独立 tab；1+2+3 收进总览电脑卡片 + 我的抽屉
- 屏幕、权限档位、设备、记住的规则、停止
- **不把外部 AI 放控制页**；外部 AI 属于智能体/工具，不是远程桌面

**我的**（左侧抽屉，QQ 式）
- 本地模式/未登录、登录 P2
- 账号与设备、通知（P2）、安装到主屏
- 当前入口、已配对设备、忘记这台设备
- 帮助/隐私/关于、团队/订阅 P2
- 右上角头像或左边缘滑动打开

## 0. 一句话

手机端只有三块地方：**我在做哪几件事**（列表）、**这一件事现在怎么样**（会话）、**这台电脑还能不能信**（设置）。
其余都是这三块的展开，不新增第四块。

拍板后的产品约束：**一次只跑一件事，但可以有好几件事摆着**（单会话执行、可切换）。

## 1. 先对齐事实：后端现在到底给什么

前端能诚实到什么程度，取决于这张表。

| 消息 | 含义 | 能不能当事实用 |
|---|---|---|
| `hello` | 项目名、任务、设备名 | 是。缺 `server_time`，倒计时只能信手机时钟 |
| `history` | 最多 400 条回放，**全局流水、不分会话**，且**已过滤审批请求** | 是。但「我批准过什么」不在里面 |
| `event.status_update.step` | 步骤四态 | 是。**唯一**能画 ✓ 的依据 |
| `event.approval_request` | 待决定（含 `expires_at`、`raw_digest`、`preview`） | 是 |
| `event.question` | 提问 | 是（当前 host-demo 未发） |
| `event.tool_result` | 执行结果 | 是（当前 host-demo 未发） |
| `chat` | 流式片段 | 是。只拼接，不加工 |
| `turn` | `running` / `idle` / `stopped` | 是，但只标「轮」的边界 |
| `notice` | `deny` / `auto` 文本 | **只能展示，不能判定**：策略拦截、产出报告、设备事件、截图失败共用它 |
| `image` | 截图（base64 data URL） | 是，但太大，建议改二进制 |
| `ack` | 我的决定被接受了吗 | 是。`requestId` 天然幂等键 |
| `device_*` | 配对 | 是 |
| 二进制帧 | 屏幕画面，2 fps，静止时零帧 | 是。不进历史、不可回放 |

**没有 session_id。** 这是「可切换」落地的第一个硬门槛：现在所有消息属于同一个进程级会话，列表里的第二条会话无法只收到自己的流水。

### 八条缺口与本轮决定

| # | 缺口 | 决定 |
|---|---|---|
| 1 | 审批决定不进历史 | 补一条审计记录进 `history`（P0） |
| 2 | 产出是 notice 文本 | 改结构化 `artifacts`（P0） |
| 3 | 没有 decision 广播 | 广播 `decision`（P0） |
| 4 | 没有 `server_time` | `hello` 带上（P0） |
| 5 | host 只服务单个 HTML | `/app/*` 静态 + SPA fallback（P0） |
| 6 | 没有会话查询 | 做 `sessions`：单执行 + 可切换（P0） |
| 7 | 没有规则查询 | 做 `rules` 查询 / 撤销（P0） |
| 8 | token 在查询串 | 改到 **hash**（P0，本阶段做） |

## 2. 信息架构

### 2.1 三张屏 + 两个常驻元素

```
        ┌──────────────┐
        │  A 会话列表   │←──────────────┐
        └──────┬───────┘               │
               │ 点一张卡（打开）        │ 左上角 ‹
        ┌──────▼───────┐               │
        │   B 会话      │───────────────┘
        └──────┬───────┘
               │ 右上角 ⋯ / 齿轮
        ┌──────▼───────┐
        │   C 设置      │
        └──────────────┘
```

常驻元素只有两个：
- **顶部一行状态**：`● 已连接 · 执行中 · 待批 1`（最多三个词）。
- **底部输入区**：只出现在 B。

**首页判据**：冷启动直接进 **B（当前活动会话）**。从 B 左上角进 A。
只有一种例外：冷启动时若发现「别的会话在等你批准」，进 **A** 并置顶该条。

**打开 ≠ 切换**：点列表里的卡只是打开看。发指令、审批、停止，都属于「控制中的那个会话」。
要把控制权挪过去，必须显式点「切到此会话」。

### 2.2 A 会话列表

回答的问题：**我在做哪几件事、哪件卡住了、我现在控制的是哪件。**

结构：状态行 → `+ 新建` → **需要你** → **当前会话** → **最近**。

四条规则：
1. **一次只跑一件事**：任何时刻至多一条会话处于 `running` / `waiting`。
2. **每条会话带控制标记**：`● 当前`（可操作）/ `○ 只读`。
3. **打开只读、切换才动**：见 2.3 的两种模式。
4. **切换是唯一需要确认的动作**：当前会话在跑时切走 = 丢掉正在干的活，所以确认一次。别的地方不多问。

卡片七个字段：

| 字段 | 例子 | 说明 |
|---|---|---|
| 标题 | 「报告转 PDF」 | 取该会话第一句人话，截断 20 字，不摘要 |
| 项目 / 电脑 | `sandbox · 这台电脑` | 未来多机时的区分 |
| 状态徽标 | `执行中` / `待批 1` / `已停止` / `空闲` | 来自 T 轴，不自己编 |
| 控制标记 | `● 当前` / `○ 只读` | 决定能不能动手 |
| 待批数 | `1` | 该会话未决策的 `approval_request` |
| 本轮产出 | `新增 2` | 有就写，没有就不写 |
| 相对时间 | `3 分钟前` | 最后一条消息时间 |

排序：需要你 → 当前 → 最近活动。

空态只有两种：
- **从未连上**：这时的 A 就是连接页（扫码 / 粘贴地址）。
- **连上但没会话**：一句话 + `+ 新建`。

```
┌──────────────────────────────┐
│ 梵境                  + 新建  │
│ ● 已连接 · 这台电脑           │
├──────────────────────────────┤
│ 需要你 (1)                    │
│ ┌──────────────────────────┐ │
│ │ ● 当前  报告转 PDF  待批 1│ │
│ │ "把报告转成 PDF，再核对…" │ │
│ │ 3 分钟前 · 本轮新增 2     │ │
│ └──────────────────────────┘ │
│ 当前会话                      │
│   （就是上面这条）            │
│ 最近                          │
│ ┌──────────────────────────┐ │
│ │ ○ 只读  整理周报     空闲 │ │
│ │ 昨天 18:20                │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ ○ 只读  核对目录   已停止 │ │
│ │ 11 月 4 日                │ │
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

### 2.3 B 会话：两种模式 + 三块区域

**模式由「打开的是不是活动会话」决定，不由用户手动切开关。**

| 模式 | 顶栏 | 输入区 | 审批卡 | 停止 |
|---|---|---|---|---|
| **活动**（`● 控制中`） | 正常 | 按 T 轴可用性 | 可点 | 可点 |
| **只读**（`○ 只看不控`） | 黄条：`只看不控 · 最后更新 12:03 ｜ [切到此会话]` | 替换成一行说明「切换后才能发指令」 | 灰显「当前不活动」 | 不可点 |

只读模式仍然要能看：完整历史、上一轮的产出清单、最后一张画面（标明时间）。
它只是**一个写操作都不发**。

**后台提醒**：别的会话收到审批时（只可能是活动会话），在你正看着的只读页顶部压一条黄色横幅：
`另一个会话需要你批准 · 去处理`。不能让人因为「看错了一页」而让 Agent 干等 180 秒。

---

**Zone 1 · 画面（悬浮小窗）**

- 右下角常驻，约 96×60，圆角；边框表示「有没有新帧」。
- 桌面静止 → 边框变灰 + 角标「静止」。**不显示「断流」**：服务端本来就不发重复帧，静止 ≠ 断线。
- 点开全屏；全屏里必须有「最后更新 12:03:41」和关闭。不做缩放、录制、回放。
- 页面不可见时不解码（省电）；断线时画面上盖「已过期 · 12:03」，不黑屏。
- 只读模式下画面照常，但角标写「非本会话」——画面是这台电脑的，不一定是这条会话的。
- 帧永远不进入时间线。

**Zone 2 · 时间线（主区，高频）**

- 单列，按「轮」分组：你的话 →（它的话 | 步骤）交错 → 阻断项 → 结算条。
- 六类条目：

| 条目 | 形态 | 规则 |
|---|---|---|
| 你 | 右对齐气泡 | 只认服务端回声，不本地画 |
| 它 | 左对齐，流式增长 | 不重排、不加粗改字 |
| 步骤 | 单行：`✓ 编辑 · 写入 report.pdf` | 高频，直接铺在主区 |
| 审批 | 整宽卡片，左侧色条 | 自动滚到它，但用户手动上翻后不抢 |
| 系统条 | 窄字，`deny` 红 / `auto` 灰 | 只表示「要不要你看」，不承担语义 |
| 结算条 | `本轮产出：新增 2 · 改动 1 · 删除 0` | 一轮一条 |

- 长内容默认折叠：diff 折成 `+12 −3`，命令折成一行；点开全屏，不横向滚动。
- 回放 400 条到达顶部时写一句「更早的记录不在手机上了」，不装看不见。

**Zone 3 · 产出（结算条 + 抽屉）**

- 每轮结束一条结算条：`新增 2 · 改动 1 · 删除 0`，后面跟前两个文件名。
- 点开 → 底部抽屉：按新增 / 改动 / 删除分组，每项 `路径 · 大小 · 时间`。
- 文件检查警告（BOM / JSON / UTF-8）置顶，因为那是「生成了但不对」。
- 手机打不开这些文件 → **不提供「打开」**，只给「复制路径」。
- 没有变化就明确写「本轮没有动文件」。

**输入区**

- 单行自适应 1–4 行；右侧是**发送 / 停止二选一**，不做两个并排按钮。
- 上方一行 hint 永远回答「为什么现在不能发」，不写「空闲」这种废话。
- 发送后不本地画气泡：等 `user` 回声。2 秒没回声显示「发送中」，失败退回输入框并保留草稿。
- 不做引用回复、不做附件（v1 无后端）。

**审批卡（B 里最重要的一块）**

- 三行事实 + 一行范围：动作原文（等宽）/ facts 标签 / diff 折叠 / 倒计时。
- 按钮：拒绝（次）· 批准（主）；下面一行「记住这个选择（以后不再问）」是**范围开关**，勾上后主按钮变「批准并记住」。
- 决定后卡片变成落款：谁、什么时候、哪种范围。**不是消失**——消失等于不让人回看自己批准了什么。
- 倒计时到 0 或 `ack(false)` → 灰卡「已失效」，按钮不可再点。
- 「记住」不二次确认，但设置页必须能逐条撤销（见 2.4）。

```
┌──────────────────────────────┐
│ ‹ 会话   sandbox   ● 执行中   │ ← 顶部一行状态
├──────────────────────────────┤
│ 你 09:41                      │
│ ┌────────────────────┐        │
│ │ 把桌面的报告转成PDF │        │
│ └────────────────────┘        │

│                    │ 画面 ▸ ││ ← 悬浮小窗（静止时灰边）
```

### 2.4 C 设置：四组

| 组 | 内容 | 现在的数据支撑 |
|---|---|---|
| 连接 | 当前地址（不含 token）、二维码（电脑端生成，带 `#token`）、局域网/公网（按域名推断，标「推测」）、重新连接、最近 3 条错误 | 地址本地有；二维码要后端 |
| 设备 | 本机名字、已授权设备、新设备需确认、撤销 | P1，先灰显 |
| 规则 | **已记住的规则（逐条删除，立即生效）**、禁止清单（只读）、审批 180 秒超时；同一动作第 3 次只提醒、不自动拒 | 本阶段做（P0） |
| 会话 | 切回活动会话、清理本机会话记录、停止并强制终止（仅活动会话） | 部分 |

三条死规矩：
1. 没有后端支撑的项**一律灰显 + 「需要电脑端支持」**，不写「即将上线」。
2. 设备组必须有一句实话：**「服务重启后，第一台设备会重新认定」**（配对只存内存）。
3. 规则删除必须写清作用域：删掉的是「记住的那一类」，不是「已经发生的那一次」。

### 2.5 不做什么

不做仪表盘/统计图、不做「AI 总结这轮干了什么」、不做进度百分比（没有总量，别编）、不做多标签工作区、不做文件上传（v1 无后端）、不做「同时跑两个会话」。

## 3. 状态机

### 3.1 不要用一个枚举

「连接中 / 已连接 / 等待确认 / 审批中 / 执行中 / 已停止 / 断线重连 / 只读」是**五个不同维度**的东西。
压进一个枚举，第一次断线就爆炸：断线时它既在「执行中」又在「重连中」。

拆成五条正交轴，UI 是它们的函数：

| 轴 | 取值 |
|---|---|
| **L 连接** | `boot` → `connecting` → `open` → `pairing_pending` → `ready` / `reconnecting` / `rejected` / `denied` / `offline` |
| **T 轮次**（只对活动会话） | `unknown` / `idle` / `running` / `waiting` / `stopped` / `error` |
| **A 审批**（每个请求一份） | `offered` / `submitting` / `resolved` / `expired` / `stale` |
| **D 本机** | `trusted` / `pending` / `denied` |
| **S 视图** | `active`（控制中）/ `viewing`（只看不控）/ `switching`（切换中）/ `blocked`（要切但它在跑，出确认层） |

S 是**相对「当前打开的那条会话」**说的：同一条会话，活动时是 `active`，不是活动时是 `viewing`。
T 只对活动会话有意义；`viewing` 显示的是历史快照，不参与实时状态。

### 3.2 L 连接

| 状态 | 怎么进来 | 顶栏 | 内容区 | 输入 | 唯一能点的 |
|---|---|---|---|---|---|
| `connecting` | 启动 / 重连 | 灰点「连接中…」 | 骨架屏 | 禁用 | 无 |
| `open` | 通道通了，还没 `hello` | 蓝点「同步中」 | 旧内容灰一档 | 禁用 | 无 |
| `ready` | `hello` + `history` 到手 | 绿点「已连接 · 设备名」 | 正常 | 按 T/S | 发送 |
| `pairing_pending` | 收到 `device_pending` | 黄点「等待确认」 | 一张说明卡：设备名/IP/请在已有设备上点允许 | 禁用 | 无（不自动重试） |
| `denied` | close 4004 | 红点「已拒绝」 | 说明 + 重新扫码 | 禁用 | 「重新连接」 |
| `rejected` | close 4001 | 红点「口令无效」 | 说明 + 重新扫码 | 禁用 | 「重新扫码」 |
| `reconnecting` | 曾 `ready` 后断开 | 黄点「重连中 · 第 n 次」 | **保留** feed 与最后一帧画面 | 禁用 | 「立刻重试」 |
| `offline` | 退避超过 30 秒 | 红点「连不上」 | 同上 + 排查提示（端口 / 隧道地址变了） | 禁用 | 「重试」 |

禁止：
- `rejected` / `denied` 不自动重试（重试一万次也还是错口令）。
- `pairing_pending` 不显示历史、不显示画面（服务端本来也不给）。
- 任何非 `ready` 状态都不许把 T 轴改成「已停止」——不知道就是不知道。

### 3.3 T 轮次（活动会话）

| 状态 | 判据 | 主区 | 输入 | 主按钮 |
|---|---|---|---|---|
| `unknown` | 刚同步、无 `turn` / `status_update` | 「正在读取状态」 | 禁用 | 无 |
| `idle` | 最近 `turn=idle` 或 `status_update.state=idle\|done` | 时间线静止 | 可用 | 发送 |
| `running` | `turn=running` 或 `state=running` | 步骤推进，最新步骤高亮 | 草稿可编辑，**发送禁用** | 停止 |
| `waiting` | 存在未决策的审批/提问 | 自动定位到卡片 | **发送禁用** | 批准/拒绝 + 停止 |
| `stopped` | `turn=stopped` | 停止说明 + 本轮不做出产判定 | 可用 | 发送（**并提示下一句开新会话**） |
| `error` | `status_update.state=error` | 错误原文 | 可用 | 发送 |

`running` 与 `waiting` 是包含关系，不是并列：`waiting` 时 Agent 仍在跑，只是卡在等人。

### 3.4 A 审批（每个请求一份）

| 状态 | 进入 | 卡片 | 按钮 | 允许 |
|---|---|---|---|---|
| `offered` | 收到 `approval_request`，未点 | 高亮 + 倒计时 + 事实三行 | 拒绝 / 批准 / 记住开关 | 点一次 |
| `submitting` | 已点，未收到 `ack` | 按钮禁用 + 「提交中」 | 无 | 8 秒后可「重试」（同 `requestId`，天然幂等） |
| `resolved` | `ack.accepted=true` | 落款：谁、何时、哪种范围 | 无 | 只读；可从设置撤销该规则 |
| `expired` | `now > expires_at`，或服务端 `forget` | 灰卡「已过期」 | 无 | 只读 |
| `stale` | `ack.accepted=false` | 灰卡「已失效（超时或另一台设备已处理）」 | 无 | 只读 |

`ack(false)` 是**终态**，不重试、不重新弹窗。

### 3.5 S 视图与组合

| S | 判据 | 顶部/横幅 | 输入 | 审批卡 | 停止 |
|---|---|---|---|---|---|
| `active` | 打开的 == 活动会话 | 正常 | 按 T | 可点 | 可点 |
| `viewing` | 打开的不是活动会话 | 黄条：`只看不控 · 最后更新 12:03 ｜ [切到此会话]` | 替换成说明 | 灰「当前不活动」 | 不可点 |
| `switching` | 已发起切换，等 attach + history | 「正在切换…」 | 禁用 | 灰 | 禁用 |
| `blocked` | 点了切换，但活动会话在跑 | 底部确认层：`sandbox 正在执行。停止并切换？` `[停止并切换] [取消]` | 禁用 | 保留 | 可点 |

**连接 × 轮次（仅 `active`）**：

| L \ T | idle | running | waiting | stopped / error |
|---|---|---|---|---|
| `ready` | 输入 + 发送 | 草稿可编辑、停止可点 | 只审批 + 停止 | 输入 + 发送（附提示） |
| `connecting` / `reconnecting` | 全禁用，内容保留 | 全禁用；进度停在最后一步，标「最后更新 12:03」 | 卡片灰、标「恢复后可操作」 | 全禁用 |
| `pairing_pending` / `denied` / `rejected` | 全禁用，只有一个按钮 | 同左 | 同左 | 同左 |

S 的合并规则：
- `L=ready && S=viewing` → **永不可写**，与 T 无关。
- `L≠ready` → 全禁；`viewing` 的历史上还要标「快照可能不是最新」。
- `S=blocked` 是唯一允许「先停止、再切换」的地方。

### 3.6 十条不变式（真前端翻车都在这）

1. **连接轴、会话轴、轮次轴正交。** 文案只能落在一条轴上：断线不许出现「已停止」，只读不许出现「正在执行」。
2. **断线不清屏。** 保留画面与时间线，但所有「实时」标记换成时间戳；恢复后由 `history` 覆盖，不由本地补。
3. **只有 `step.status` 和 `tool_result` 能画 ✓。** Agent 在聊天里说「已完成」不算。
4. **审批点一次就锁。** 以 `ack` 为准；`accepted=false` 是终态；重试只能复用原 `requestId`。
5. **回放不产生副作用。** `history` 重建期间不滚动、不响、不补发 `resync`、不插卡。
6. **单一事实源。** 屏幕上每一条都来自服务端消息；本地只允许两种临时态：草稿、提交中。
7. **所有倒计时用 `expires_at`。** 与手机时钟偏差 > 30 秒时，在设置里提示「手机时间可能不准」。
8. **帧不进时间线、不落历史、不可回放。** 它只是「现在长什么样」。
9. **只读会话零写操作。** `prompt`、`stop`、`decision` 一个都不发；要动，先切过去。
10. **token 只存在于内存与 `sessionStorage`。** URL 里出现一次就抹掉；任何日志、错误文案、复制文本都不回显。

### 3.7 关键转移（文字时序）

- **发送**：`ws.send(prompt)` → 等服务端 `user` 回声 → 气泡出现 → `turn running` → 步骤推进 → 结算条 → `turn idle`。
- **打开只读**：点列表里非活动会话 → attach（只读）→ 后端回该会话 `history` → 换模型 → `viewing`。活动会话的实时事件只更新列表徽标，不进当前时间线。
- **切换**：点「切到此会话」→ 活动会话 T ∈ {`running`,`waiting`} → 确认层 → 发 `stop` → 等 `turn stopped` → detach / attach（目标）→ 清空模型 → `history` → `active`。
- **后台提醒**：非当前打开的会话收到审批 → 顶部黄条「另一个会话需要你批准 · 去处理」。
- **断线重连**：close → 保留画面与 feed → 顶栏「重连中 n」→ 退避 0.8 / 1.6 / 3.2 / 8 秒 → `open` → `hello` + `history`（当前打开的会话）→ `ready`。页面可见时立即重连；4001 / 4004 不重试。
- **回放**：`history` 到达 → 置 `replaying` → 重建模型 → 清除 → 不做任何滚动/提示。
- **停止**：点停止 → 「正在停止」（**不是**「已停止」）→ 3 秒内自己停就正常结束；3 秒后服务端硬杀 → `turn stopped` + 常驻提示「下一句会开新会话」，直到下一次发送。
- **审批超时**：倒计时到 0 → 卡片 `expired`；服务端 180 秒后自动拒并 `forget`。若此时再点批准 → `ack(false)` → `stale`。
- **撤销规则**：设置页删除一条规则 → 下一次同类动作重新弹卡（不需要断开重连）。
- **画面**：在线但 5 秒无新帧 → 「画面无变化」；30 秒无新帧 → 「画面可能停住了」（弱提示，不是错误）；断线 → 盖「已过期 12:03」。

## 4. 技术选型

### 4.1 结论

| 项 | 选择 | 理由 |
|---|---|---|
| 构建 | **Vite + React 19 + TypeScript** | 一条命令出静态产物，和 host 同仓 |
| 框架 | **不用 Next.js** | 没有 SSR/SEO 需求，多一层运行时只增加出错面 |
| 状态 | **zustand + 纯 `reduce(state, msg)`** | 3 个屏不值得上 redux；纯函数才能用历史回放测状态机 |
| 路由 | **hash + `popstate`，不引路由库** | 3 个路由，手机返回手势能用即可 |
| 样式 | **CSS 变量 + CSS Modules** | 无设计系统需求；Tailwind 也行，但不为此引工具链 |
| 测试 | **Vitest + `history.jsonl` 回放** | 真数据比手写 fixture 更能暴露状态机漏洞 |
| 包体积 | 首屏 < 120 KB gzip | React 45 + 其余；zod 只进 dev |

### 4.2 包与集成

```
packages/web/
  src/main.tsx
  src/app/       三个屏幕、路由、根布局
  src/model/     reduce.ts（纯函数）、selectors.ts、types.ts
  src/net/       ws.ts（连接/退避/可见性）、frames.ts
  src/ui/        审批卡、步骤行、输入区、结算条、画面小窗、确认层
  test/          fixtures + reducer 快照
```

- 构建产物在 `packages/web/dist`（Vite 默认）；host 用 `webDir` 托管 `/app/*` 并做 SPA fallback（见 ADR-0007）。
- 开发：`vite` 起 5173，`server.proxy` 把 `/ws` 转给 8787。token 在前端读，不走代理配置。
- 生产：一次 `pnpm --filter @vance/web build`，`v` 照旧只起一个端口。
- 测试台 `public/index.html` 保留为诊断页，不再加功能。

### 4.3 状态组织

- 一个 store，五个切片：`link` / `session`（`activeId`、`openedId`、`list`）/ `turn` / `approvals` / `timeline`。
- 所有变更只走 `reduce(state, msg)`；组件只读 selector，不自己推状态。
- 时间线归一化成 `Map<id, Item>` + `order: string[]`，按轮分组渲染；流式 `chat` 用 `requestAnimationFrame` 合并，避免每帧重渲染。
- 切换会话 = 清空 timeline/approvals/turn，等新的 `history` 重建。**不做增量合并**，两段流水混在一起是灾难。

### 4.4 网络层

- **token 在 hash**：电脑端二维码带 `#token=…`；前端启动读 `location.hash` → 存 `sessionStorage` → `history.replaceState` 立刻抹掉 hash → WS 用 `?token=` 连（WS 不走 HTTP 访问日志）。
- 页面加 `<meta name="referrer" content="no-referrer">`；错误文案、日志一律不回显 token。
- 退避：0.8 → 1.6 → 3.2 → 8 秒封顶，带抖动；`visibilitychange` / `online` 立即重连。
- 4001（口令）/ 4004（被拒）不重试。
- 二进制帧只保留最后一帧，旧 blob URL 立刻 `revoke`；页面隐藏时丢弃。
- `resync` 只在「本机看到 running → 非 running」且非回放时发（现有注释里的坑，照抄）。
- 所有入站消息带 `session_id`（后端 P0 补）；不是当前 `openedId` 的，只更新列表徽标与后台提醒，不进时间线。

### 4.5 移动端细节

- 安全区 `env(safe-area-inset-*)`；命中区 ≥ 44px；发送/批准在拇指区。
- `prefers-reduced-motion` 下关掉脉冲与自动滚动动画。
- 审批卡用 `role="alertdialog"` + 焦点管理，读屏能念出「动作 + 倒计时」。
- 深色优先（这产品多在夜里/外出用），浅色跟随系统。
- 360×640 到 430×932 不出现横向滚动。

### 4.6 不做

SSR、离线读写、推送通知（v1.2 再说）、图表库、UI 组件库、虚拟滚动（400 条用不上）、拖拽、富文本、文件上传、并行执行多个会话。

## 6. 验收（真机，不是截图）

1. 飞行模式 5 秒再开：不清屏；顶栏「重连中」；恢复后 3 秒内与电脑一致；**没有**把运行中误报成已停止。
2. 电脑上审批已超时自动拒，手机再点批准：显示「已失效」，不重试。
3. 两台手机同时看：一台批准，另一台 2 秒内卡片变「已由另一台处理」。
4. 断网 30 秒：画面小窗显示「最后一张 12:03 · 已过期」，不假装实时。
5. 桌面静止 1 分钟：0 新帧，但显示「画面无变化」，不是「断流」。
6. 执行中锁屏 10 分钟回来：一次 `resync` 拿全，不重复播报、不重复插卡。
7. 点停止：「正在停止」→ 3 秒后「已停止 · 下一句开新会话」。
8. 服务端没回声：2 秒「发送中」→ 5 秒退回输入框并保留草稿。
9. **切换**：执行中切走 → 弹「停止并切换」；确认后目标会话历史完整，旧会话在列表里变「已停止」。
10. **只读**：打开非活动会话，输入禁用、审批灰；切回去之后，之前那段历史不重复、不丢失。
11. **两个会话的流水不串**：在 A 会话跑着，打开 B 看历史，B 里不出现 A 的步骤。
12. **token**：打开后地址栏里没有 token；刷新不断线；把去掉 hash 的地址发给另一台手机 → 能打开页面，但连不上。
13. **撤销规则**：设置里删掉一条记住的规则，下一次同类动作重新弹卡，不用重启服务。
14. 360×640 到 430×932：无横向滚动；单手能够到发送与批准。
15. 深色 + 强光下：状态色可辨；色盲模式下靠文字而非只靠红绿。
