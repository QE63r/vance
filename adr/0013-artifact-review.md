# ADR-0013：交付物检阅（artifact review）

- 状态：已接受
- 日期：2026-11-08
- 关联：ADR-0002（审批绑字节）、ADR-0004（不做摘要）、ADR-0009（产出结构）

## 背景

审批只做了“事前拦风险”。活干完之后，客户还看不到交付物：
产出清单只有文件名，手机上打不开，确认/打回无从谈起。

而且这一层不能用 AI 摘要替代：摘要一加，客户批的是我们的转述，不是原件。

## 决定

### 一、取件单，不是主 token

`POST /artifacts/ticket`（头 `x-vance-token`，body `{ path }`）：
- path 必须**精确命中当前会话最近一次产出**的 added/changed，否则 404；
- 签发时算 sha256、记大小与 content-type；
- 票据 60 秒、只对应这个文件；`GET /artifacts/<ticket>` 取字节；
- 过期 410，未知票 404；票据本身是短期凭证，取文件不再要主 token。

主 token 永不进 URL。

### 二、验收绑 sha256

`POST /artifacts/accept`（头 token，body `{ ticket, decision, note? }`）：
- 重新读文件、重算 sha256；
- 与票里的不一致 → **409 文件已变化，请重新查看**；
- 一致 → 流水写 `artifact_decision`（path / sha256 / decision / by / at / session_id）；
- reject 且带意见 → 作为 `交付物未通过：<note>` 交给现有 prompt 流程。

“你确认的就是你看到的字节”，这是验收的定义，不是附加功能。

### 三、只呈现原件

- 图片、PDF、纯文本直接预览；docx/xlsx 只给**下载原件**，不做文本抽取/格式转换；
- 不做 AI 摘要、转写、要点提炼；
- 不做任意文件浏览器：只认产出清单；
- 只读：不写、不删、不改名、不上传。

### 四、审计语义

验收后文件又被改，旧验收不自动作废；下次预览会显示新哈希，界面提示“文件已变化”。
历史里的 sha256 是当时那份字节的指纹，不假装它永远有效。

## 后果

- 手机能读交付物并决定收不收，控制面闭环；
- PDF 预览依赖浏览器；docx/xlsx 这一版只能下载；
- 票据 60 秒对超大文件可能偏短（v1 可调）；
- 测试 124 → 130（host +6）。

## 失效条件

- 若允许 path 来自产出清单之外，第一条失效；
- 若验收不重算 sha256，第二条失效；
- 若加“AI 摘要”作为默认视图，第三条失效。
