# ADR-0003：成本结构，以及「配置」这条边界

- 状态：已接受
- 日期：2026-11-02
- 关联：ADR-0002（事件信封）

## 背景

梵境是轻控制面：不跑模型、不托管 Agent。做这个选择的**根本原因是成本**——
如果梵境在链路里调用模型，边际成本会随客户用量线性增长，而收入是按人头固定的
（$12/月/人）。重度用户越多，毛利越薄。

但这条原则被误用到了另一件事上：「不替用户配置 Agent」被当成了成本决策。
实际上改一行配置文件不产生任何 token 消耗，两者不在同一个轴上。

## 决定

### 一、核心链路不产生按用量计费的成本

- 判定、拦截、审批、审计：全部确定性代码，零调用成本。
- 任何 LLM 能力（例如审批卡片的「意图摘要」）必须同时满足三条：
  1. 跑在**用户自己的 key** 或本地模型上；
  2. **可关闭**，关掉之后核心功能不受影响；
  3. **不在关键路径上**——它挂了，审批流程照常走。
- 任何使边际成本随用量增长的功能，默认不做。必须做时，成本转嫁到用户 key 或本地。

### 二、边界重新表述

**不做**：替用户安装 / 升级 / 修复 Agent；代持模型凭据；托管 Agent 运行。

**可以做**：替用户打开「先问人」这一类开关（例如 opencode 的 `permission: ask`）。

理由：那不是改变 Agent 怎么工作，而是决定**人是否在场**。成本为零，责任有限。

### 三、判断顺序

- 涉及**钱** → 看第一条。
- 涉及**支持与责任** → 看第二条。
- 两者别混。混在一起，会把「免费的动作」误判成「昂贵的能力」。

## 后果

- 安装流程里会出现「帮你打开审批开关」这一步，属于边界内的例外，文档中需显式说明。
- 若将来提供托管模型或云端代跑（会消耗 token），必须单独立项，且定价按用量转嫁。

## 失效条件

若模型价格降到可忽略（例如本地推理零边际成本普及），第一条可以放宽；
但「收入固定、成本浮动」这个结构性风险仍然成立，放宽前要先改定价模型。
