# ADR-0002：事件信封与批准绑定

- 状态：已接受
- 日期：2026-11-02
- 取代：无（ADR-0001 仍然有效）

## 背景

D2–D4 这一步要定的是"批准的到底是什么"。这件事一旦写进线上格式就改不动了，
所以先把决定和理由固定下来。

原设计有两个隐藏假设，都不成立：

1. 假设"动作可以被规范化成一个稳定的摘要"——于是批准绑定的是我们对动作的**理解**。
2. 假设"发送方可以声明风险等级"——于是适配器有权把自己标成低风险，绕过审批。

## 决定

### D1　批准绑定原始字节，不绑定任何转述

批准的对象是**这一次请求的原始 payload 字节**，摘要记为 `raw_digest`（sha256 hex）。

配套三条：

- **传输层原样透传**：不格式化、不重排字段、不"解析后再拼回去"。
- **展示层原文优先**：手机上先给原文，可读渲染放在旁边，且必须标注"这是渲染"。
- **执行层比对**：执行前把要跑的字节与已批准的字节逐字节比较，不一致即中止。

`raw_ref` 记录原文存放位置与长度，审计时可取出当时那一串字节。

**为什么不做规范化**：规范化会引入一个"我们认为等价的映射"。一旦映射有偏差，
批准的就是另一个动作。而"同一个意图换个写法"本来就该**重新问人**——
一次批准只对应一次请求。

**代价**：Agent 换个写法就要再批准一次，用户会觉得啰嗦。这是有意接受的：
在安全产品里，"多问一次"远好于"批了别的东西"。

### D2　风险由治理层计算，发送方无权声明

schema 中删除 `risk` 字段。事件只携带**动作 + 确定性事实**（文件数、行数、
是否在 git 跟踪内、是否可恢复）。风险等级由本地规则引擎根据事实计算。

**为什么**：如果适配器能声明 `risk: "low"`，一个跑飞的 Agent 只要自报低风险，
就能拿到静默放行。这是威胁模型里"适配器谎报"那条的唯一解法——不是靠信任，是**不给它这个权力**。

### D3　事件不可变，结果独立成事件

不复写原事件。执行结果以 `tool_result` 事件追加，通过 `for_raw_digest` 指回原请求。

**为什么**：审计要能证明"当时批的就是这个"。一条被改过的事件不能当证据。

### D4　时间以 Host 为准，毫秒整数

- 以 Agent Host 的时间为准，手机只做显示。
- 全部时间字段用毫秒整数。
- 过期判断容忍 ±2 秒时钟偏移（可配置）。

### D5　未知字段：审批类严格，状态类宽容

- `approval_request` / `question`：`.strict()`，出现未知字段直接判为非法。
- `tool_result` / `status_update`：忽略未知字段。

**为什么**：未知字段可能携带我们没看见的额外指令，批准一个自己没看全的动作很危险；
而纯状态汇报多一个字段无所谓。

### D6　不截断数据，只折叠展示

- 完整输出永久保留，可导出、可搜索。
- 界面默认只显示"结论行"（退出码、错误行、增删统计）。
- 折叠处必须写明"还有 N 行未展开"。
- 禁止任何"看起来完整其实被截过"的呈现。
- 高风险操作的卡片，摘要不得作为唯一内容。

### D7　拦截降级为会话级挂起（不进 P0）

逐条动作拦截不进 P0。理由是：业务调用频繁，逐步过滤会严重伤害体验；
且 Agent 被拦后往往会换一种写法绕过，逐条拦截等于打地鼠。

P0 交付的是**会话级挂起**：拒绝一条之后，若同一 Agent 继续尝试绕过，
则挂起整个会话（暂停进程 / 断开 PTY），而不是逐条批评。

**边界说明**：这意味着 v1 的保证是"确保人看到并批准的就是那一次请求"，
**不是**"确保恶意 Agent 无法执行"。文档与对外表述必须按这个口径写，
不得声称已有系统调用级强制拦截。

## 后果

- 线上格式只认 `raw_digest`，没有 `action_digest`。
- 适配器的责任变重：它必须能给出原文，而不是"翻译后的好句子"。
- 同一动作换个写法会触发二次审批。
- 安全主张的措辞必须收窄（见 D7 边界说明）。

## 失效条件

若将来出现"Agent 侧原生支持对请求签名"的通用机制，`raw_digest` 应改为
直接使用 Agent 的签名作为绑定对象，我们不再自己算。
