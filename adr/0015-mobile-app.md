# ADR-0015：手机 App v0（PWA）

- 状态：已接受（代码完成，待 Android 真机装主屏验收）
- 日期：2026-11-09
- 关联：ADR-0014（固定入口与设备记住）、`docs/task-mobile-app.md`、`adr/0014-fixed-entry.md`

## 背景

入口已经固定，设备批准已经落盘；手机端还差最后一层：每次都要开浏览器、找地址。
目标是把现有 React 页面做成可安装的 PWA：第一次扫码/粘贴，之后打开主屏图标直接进。

## 决定

### 一、形态：PWA，不包 APK

- `manifest.json`：名称「梵境 Vance」、短名「梵境」、`display: standalone`、
  `start_url`/`scope` 都在 `/app/`
- service worker 只缓存 `/app/` 壳和带哈希的 assets；不缓存 WebSocket、审批、产出
- 图标 192 / 512 / maskable；沿用 `assets/vance-icon.ico` 的「碎环 + 星」Logo
- 不做推送、后台常驻、生物识别、多用户、应用商店；APK 留到下一阶段

### 二、凭据只存浏览器本地

- `localStorage` 存 `vance_endpoint` + `vance_token`
- 旧版的 `sessionStorage` token 启动时一次性搬过去，避免当前这台手机重扫
- 不假装是硬件安全存储；PWA 的 token 可能被同源脚本读到，这是已知边界
- `deviceId` 继续留在 `localStorage`：重配对还是同一台设备，服务端已批准

### 三、配对页

- 没有凭据、口令错、设备被拒时显示配对页；不再显示一个连不上的会话壳
- 粘贴完整地址（`?token=` 或 `#token=`）→ 存凭据 → 重载
- 不做应用内相机扫码：用系统相机扫电脑上的二维码，打开的就是带 token 的地址；
  配对页只负责“没有二维码/链接可用”时的粘贴兜底
- 装了 PWA 的入口只能连这个入口；粘贴别的电脑地址会跳到那台电脑的 `/app/`，
  让那台电脑自己配对（一个安装一个入口）
- 「忘记这台设备」清本地凭据回配对页；不删电脑上的已批准设备记录

### 四、错误路径

- WebSocket 4001（口令错）/ 4004（设备被拒）：清本地凭据，停在配对页并显示原因，
  不自动重连
- 断网/重连仍走原来的退避 + `visibilitychange`/`online` 立即重连；这一版不改

## 后果

- Android 可“添加到主屏幕”，全屏打开；关掉重开不扫码
- 入口变化/换电脑时，需要在新入口重新安装（PWA 的 origin 边界）
- service worker 可能缓存旧壳：升级时改 `CACHE` 版本；这一版 v1
- 测试 133 → 140（web 8 → 15）；新增配对链接解析、凭据存取、URL 优先、
  dev/生产兜底、4001/4004 不重连
- 真机装主屏的截图仍需补；这是 ADR 状态保留“待验收”的原因

## 失效条件

- 若 token 被移到 URL/其他可被第三方读到的位置，第二条的“只存本地”失效
- 若在配对页加入“任意 origin 的 API 调用”，第三条的“一个安装一个入口”失效
- 若 service worker 开始缓存 `/ws` 或审批数据，第一条的“只缓存壳”失效
